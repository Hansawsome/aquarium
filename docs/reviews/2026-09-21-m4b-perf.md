# M4b 성능 측정 (2026-09-21)

ReefM1 레벨의 프레임 시간을 개발 전용 `-AquariumFrameStats` 플래그로 측정했다.

## 측정 조건

- 해상도: 1920x1080 (`-game -windowed -ForceRes`), 텍스처 스트리밍 끔
- 씬: 배경 물고기 36마리(5종) + 프롭 22개(산호 5종 PBR 3장 + 바위) + 반투명 부유 입자 커튼 3장 + 수면 고보 2장 + 플레이어 물고기 1마리
- 실행 시간 95초 중 앞 30초(워밍업: 셰이더 컴파일·스트리밍)는 버림
- `-benchmark`는 사용하지 않음 — 고정 타임스텝이 되어 DeltaSeconds가 상수가 되므로 측정에 쓸 수 없다
- 커밋: `8e8d61f`
- 머신: Apple M5

같은 커밋에서 두 번 측정했고 편차는 작다.

| 실행 | 샘플 수 | 평균 fps | p95 |

| 1회차 | 3683 | 63.2 | 17.26 ms |

M4a 대비 평균 fps가 약 38 % 내려갔다. 이번에 새로 들어간 비용 항목은 다음과 같다.

- 볼류메트릭 안개 격자 품질 상향 — `r.VolumetricFog.GridPixelSize=4`, `GridSizeZ=128`
  (기본 8/64 대비 화면 타일 수 4배 × Z 슬라이스 2배)
- 그림자를 드리우는 수면 고보 평면 **2장** (거친층 스케일 200 = 200 m, 고운층 60 m)
- 반투명 부유 입자 커튼 3장 — 가장 가까운 장은 X=90 cm로 화면 대부분을 덮는 오버드로
- 프롭 14개 → 22개, 전부 BaseColor/Normal/Roughness 3장 PBR
- 후처리에 SSAO(`ambient_occlusion_intensity=0.5`, 반경 80)와 블룸 추가

## 예산 판정: 컷 없음

계획의 컷 목록(볼류메트릭 격자 되돌리기 → 근거리 커튼 제거 → 볼류메트릭 거리 6000→4000 →
프롭 22→16 → AO 끄기)은 **평균 60 fps 미만일 때** 적용하기로 되어 있었다.
측정값 62.8 fps / p95 17.49 ms는 SRS 목표(평균 60 fps, p95 ≤ 22 ms)를 **둘 다 충족**하므로
컷을 하나도 적용하지 않았다. 따라서 Task 10 캡처는 실제로 출하되는 설정 그대로다.

**여유가 크지 않다는 점은 그대로 남는다.** 60 fps 대비 여유가 약 5 %뿐이고, M4a에는 40 fps의
여유가 있었다. 설계 에이전트는 볼류메트릭보다 반투명 커튼이 더 위험하다고 예측했는데, 이번
측정은 항목별 분해를 하지 않았으므로 **어느 쪽이 주범인지는 측정으로 확인되지 않았다.**
M5·M6에서 씬에 무언가를 더 얹는다면 먼저 위 컷 목록 1·2번을 항목별로 측정해 예산을 되찾아야 한다.

## SRS 목표 대비

SRS 성능 목표는 "평균 60fps, 95백분위 ≤ 22 ms"이며, **판정은 M6**에서 한다.
이 수치는 에디터 바이너리로 측정한 중간 참고값이다.
