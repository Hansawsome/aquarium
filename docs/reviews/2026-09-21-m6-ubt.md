# M6 — UBT 앱 마무리(exit 65) 진단

작성일: 2026-09-21 · 환경: Xcode 27.0 (Build 27A266a) / MacOSX27.0.sdk / UE 5.8.2 / macOS 27.0

## 증상

게임 타깃(`Aquarium Mac Development`)을 UBT로 빌드하면 컴파일·링크는 끝까지 성공하고
`Binaries/Mac/Aquarium`(441 MB)까지 나오지만, 마지막 `[25/26] ApplePostBuildSync` 단계가 실패한다.

```
[25/26] ApplePostBuildSync Executing PostBuildSync [.../Binaries/Mac/Aquarium] [NoUba]
Run pre-actions
SchemeAction Touch\ UBT\ generated\ tiles /var/folders/.../T/SchemeScriptAction-VYRWFE.sh
ComputePackagePrebuildTargetDependencyGraph
** BUILD FAILED **
The following build commands failed:
	Run custom shell script 'Touch UBT generated tiles'
	eyJ0eXBlIjp7IndvcmtzcGFjZSI6e319fQ==
(2 failures)
ERROR: Failed to finalize the .app with Xcode. Check the log for more information
Result: Failed (OtherCompilationError)
```

**2026-09-21 현재 환경에서 재현된다.** UBT는 실패하면 `-hideShellScriptEnvironment` 없이 한 번 더
돌려 환경 변수를 전부 찍는데, 두 번째 시도도 같은 지점에서 같은 모양으로 끝난다.
두 번째 실패 줄 `eyJ0eXBlIjp7IndvcmtzcGFjZSI6e319fQ==` 는 base64로 `{"type":{"workspace":{}}}` —
XCBBuildService가 워크스페이스 수준에서 돌려준 불투명한 진단이고, 사람이 읽을 메시지가 없다.

### 선행 결함 (이 진단 과정에서 별도로 발견)

처음 재현 시도는 App finalization까지 가지도 못하고 **컴파일에서** 죽었다.

```
Tests/ControllerTests.cpp:8:10: fatal error: 'Tests/AutomationEditorCommon.h' file not found
Tests/NameTagTests.cpp:3:10:   fatal error: ...
Tests/SessionTests.cpp:5:10:   fatal error: ...
```

`AutomationEditorCommon.h`는 `UnrealEd`(에디터 전용)에 있고, `Aquarium.Build.cs`는
`if (Target.bBuildEditor)`일 때만 `UnrealEd`를 붙인다. 그런데 이 테스트 파일들의 가드는
`#if WITH_DEV_AUTOMATION_TESTS` 하나뿐이었고, 이 매크로는 **게임 Development 빌드에서도 1**이다.
즉 **게임 타깃은 M6 이전까지 한 번도 성공적으로 빌드된 적이 없다.** 계획서(및 M0 기록)의
"게임 타깃 컴파일은 성공한다"는 전제는 틀렸다.

가드를 `#if WITH_DEV_AUTOMATION_TESTS && WITH_EDITOR`로 좁혀 고쳤다
(`FishActorTests.cpp`, `ControllerTests.cpp`, `NameTagTests.cpp`, `SessionTests.cpp` 네 파일).
그러고 나서야 위의 App finalization 실패가 드러났다.

## 확인한 사실

| # | 확인 | 명령 | 결과 |
|---|---|---|---|
| D1 | UBT가 실제로 실행한 xcodebuild 명령 | 빌드 로그의 `params:` 줄 | `UBT_NO_POST_DEPLOY=true .../xcodebuild build -workspace .../Aquarium_Mac_Aquarium.xcworkspace -scheme Aquarium -configuration Development -destination generic/platform=macOS CODE_SIGN_ALLOW_ENTITLEMENTS_MODIFICATION=YES -allowProvisioningUpdates UE_XCODE_BUILD_MODE=PostBuildSync -hideShellScriptEnvironment` |
| D2 | `Touch UBT generated tiles` pre-action 본문 | 생성된 `Aquarium.xcscheme`의 `scriptText` | 세 개의 `if` 블록뿐: ① `${PROJECT_DIR}/${INFOPLIST_FILE}`가 없으면 `touch` ② `${CONFIGURATION_BUILD_DIR}/${PRODUCT_NAME}.app`가 심볼릭 링크면 `rm` ③ `PLATFORM_NAME`이 iphoneos/appletvos면 `cookeddata` 디렉터리 생성 |
| D2b | 본문을 실제 환경 변수로 손수 재생 | `env PROJECT_DIR=... INFOPLIST_FILE=... PLATFORM_NAME=macosx /bin/sh -c '<본문>'` | **exit 0.** 세 분기 모두 무해하다. plist는 이미 존재(`Build/Mac/Resources/Info.Template.plist`, 384 B), `.app`은 심볼릭 링크가 아니고, macOS라 ③은 건너뛴다. **스크립트 본문은 실패 원인이 아니다.** |
| D3 | 같은 명령을 손으로 실행 + result bundle | D1 명령 + `-resultBundlePath` | **`** BUILD SUCCEEDED **`, exit 0.** `xcresulttool`의 `errorSummaries`/`warningSummaries` 모두 **빈 배열** — pre-action이 숨긴 경고조차 없다. 결과물은 완전한 `Aquarium.app`(Info.plist, `_CodeSignature`, `MacOS/Aquarium`, `Resources/AppIcon.icns`·`Assets.car`·`UEMetadata`)이고 `codesign -dv`가 adhoc 서명을 확인한다. |
| D3b | 손 실행이 상태를 고쳐 놓은 뒤 UBT 재실행 | `Build.sh Aquarium Mac Development` | **여전히 exit 6, 같은 실패.** 따라서 "선행 상태가 없어서" 실패하는 것이 아니다. |
| D4 | 환경을 비우고 실행 | `env -i PATH=... HOME=... bash -c '<D1 명령>'` | **exit 0, BUILD SUCCEEDED.** |
| D4b | stdin을 `/dev/null`로 | `bash -c '<D1 명령>' </dev/null` | **exit 0.** |
| D4c | 작업 디렉터리를 `$TMPDIR`로 | `(cd "$TMPDIR" && bash -c '<D1 명령>')` | **exit 0.** |

## 기각한 가설

- **샌드박스** — M0에서 기각. UBT 로그에 `sandbox-exec` 호출 없음.
- **`Build/Mac/Resources` 부재** — M0에서 기각. D2b에서 plist가 실재함을 재확인.
- **`TMPDIR` 부재** — M0에서 기각. pre-action은 양쪽 모두 `/var/folders/yl/.../T/`에서 돈다.
- **pre-action 스크립트 본문의 버그** — **D2b에서 기각.** 본문은 실제 환경 변수로 exit 0이다.
  (`[[ ]]` 조건이 거짓이라 마지막 `if`가 비정상 종료 코드를 남긴다는 가설도 검정했다.
  조건이 거짓이고 `else`가 없는 `if`는 0을 돌려주므로 성립하지 않는다.)
- **셸 환경 변수 차이** — **D4에서 기각.** 환경을 비워도 성공한다. 즉 "내 셸에 있는 무언가 덕분에
  손 실행이 통한다"가 아니다.
- **stdin/tty, 작업 디렉터리** — D4b·D4c에서 기각.

## 결론

**원인 미특정.** 다만 범위는 상당히 좁혀졌다.

실패하는 것은 **명령도, 스킴도, pre-action 스크립트 본문도, 환경 변수도, cwd도, stdin도 아니다.**
완전히 동일한 명령이 셸에서는 — 환경을 전부 비워도 — 성공하고, **UBT의 액션 실행기(`[25/26]
ApplePostBuildSync`, `NoUba`)의 자식으로 돌 때만** 실패한다. Xcode가 남기는 진단은
사람이 읽을 수 없는 base64 워크스페이스 토큰 하나뿐이고, result bundle 기준으로는 오류도 경고도 없다.

**가장 유력한 남은 설명은 Xcode 버전이다.** Epic은 UE 5.8에 대해 **Xcode 26.0 최소 / 26.1.1 권장**을
문서화하고 **27.x는 언급하지 않는다.** 이 기계의 Xcode 27.0 (27A266a) + MacOSX27.0 SDK 조합은
애초에 지원 범위 밖이다. 즉 Xcode 26.1.1로 내리는 것은 **우회가 아니라 정상화**이며, 그것이
진짜 해결책일 가능성이 높다. **다만 Xcode 설치는 사용자 결정이므로 이 마일스톤에서 실행하지 않았고,
사용자에게 보고한다.**

## 패키징에 대한 영향

`RunUAT BuildCookRun`은 내부에서 UBT를 불러 게임 타깃을 빌드하므로 같은 단계를 지난다.
다행히 **D3이 확인한 대로 손 실행은 완전한 `.app`을 만들어 낸다.** 그래서
`scripts/package_mac.sh`는 이 우회를 **스크립트 안에 박아** 사람이 손으로 칠 단계를 남기지 않는다:
빌드 → (실패하면) UBT 로그에서 `UE_XCODE_BUILD_MODE=PostBuildSync` 줄을 **grep으로 회수해** 실행 →
`-skipbuild`로 쿡/스테이징. 명령은 **기억이 아니라 로그에서** 되찾는다.

주의: 계획서는 이 명령을 `Engine/Programs/UnrealBuildTool/Log.txt`에서 찾으라고 하지만
**그 파일은 이 설치본에 존재하지 않는다.** 실제 출처는 `Build.sh`의 stdout(`params:` 줄)이고,
스크립트는 그쪽을 본다.
