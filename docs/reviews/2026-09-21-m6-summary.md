# Aquarium — 프로젝트 마감 요약 (M6)

작성일: 2026-09-21 · 브랜치 `feat/m6-packaging` · M6 커밋 11개 (`6bda49d` … `f85b6e4`)
갱신: 2026-09-21 — **사용자 수동 확인 5항목 전부 수행·전부 통과.** 출하 검증표의 Shipping 두 칸이 해소되어
미판정 항목은 남아 있지 않다.

## 무엇을 만들었는가

초등학생이 한국어 별명을 입력해 입장하면 다섯 종 중 한 마리를 무작위로 배정받고, 고정 카메라
앞의 산호초 바다에서 방향키로 자기 물고기를 몰며, 배경 물고기 36마리 사이에서 아무 물고기나
클릭해 놀래킬 수 있는 macOS 네이티브 게임. 별명은 세션 메모리에만 있고 디스크에 남지 않는다.

## 테스트 집계

| 계층 | 개수 | 상태 |
|---|---|---|
| 규칙 계층 (Catch2, C++17, 엔진 비의존) | **103** | 전부 통과 (`100% tests passed out of 103`), 클린 빌드에서 `-Wall -Wextra -Wshadow` 경고 **0** |
| Unreal Automation | **60** | 전부 통과 (`Test Completed … Success` 60건, 실패 0건) |

2026-09-21 M6 최종 회귀에서 재확인했다(빌드 디렉터리를 지운 뒤 재빌드, 에디터 모듈은 규약대로 두 번 빌드).

## SRS 공식 성능 판정 — 패키지 개발 빌드

| 기준 | SRS 목표 | 실측 | 판정 |
|---|---|---|---|
| 평균 fps | ≥ 60 | **61.46** (1회차 61.45 / 2회차 61.47) | **통과** |
| p95 프레임 시간 | ≤ 22 ms | **16.58 ms** (두 실행 동일) | **통과** |

측정 조건: 패키지 **Development** 빌드, 1920×1080, 30초 예열 후 **180초**, 2회 실행.
장면은 제어 1 + 배경 36 + 프롭 22로 **SRS가 적은 것(배경 19)보다 무겁다** — 게이트를 유리하게
바꾸지 않았다는 뜻이다. 두 실행 모두 60 fps 아래로 내려가지 않았다.
예비 레버(`r.VolumetricFog.GridSizeZ` 128 → 64, +17.1 fps): **쓰지 않았다.** 커튼·SSAO도 그대로다.

**61.5 fps는 천장이 아니라 vsync 바닥이다.** 전체 프레임의 **73 %가 16.0~17.0 ms 한 띠**에 몰려
있고 최소 프레임 시간은 **3 ms**다. 엔진은 3 ms에 그릴 수 있는 프레임도 16.6 ms에 맞춰 내보내고
있다. 그러므로 이 수치를 "게이트 대비 여유 1.5 fps"로 읽는 것은 **틀렸고**, 예비 레버를 써도 이
숫자는 올라가지 않는다. 상세는 [`2026-09-21-m6-perf.md`](2026-09-21-m6-perf.md).

**M1~M5의 모든 수치는 에디터 빌드였고 SRS 판정이 아니었다. 위 표가 이 프로젝트의 첫 공식 판정이다.**

## 출하 검증

`verify_package.sh`는 Development·Shipping **양쪽에서 `VERIFY_OK`**이고, 대조군 두 개
(`control:mcp-scan`, `control:config-scan`)가 같은 실행에서 함께 빨간불을 낸다.

| 항목 | 결과 | 근거 |
|---|---|---|
| MCP HTTP 서버 배제 | 통과 | `mcp-code-absent`: 게임 번들의 실행 파일·dylib·`.modules`·스테이징 플러그인 디렉터리에서 0건(Development 14개 파일 / Shipping 12개 파일). 대조군은 엔진 MCP 플러그인 디렉터리에서 7개 파일 적중. UBT 중간 산출물로도 확인했다 — 게임 `Aquarium.rsp` 6건 → 0건, 에디터 메타데이터 16건 유지 |
| 개발 플래그 배제 | 통과 | `devflags`: Development **11/11**, Shipping **0/11**. 플래그 목록은 소스에서 뽑는다(손으로 베낀 목록은 `AquariumNoFlee`를 놓쳤다) |
| 별명 비영속(자동) | 통과 | `verify_privacy.sh auto`: `AUTO_TOTAL=2 AUTO_ECHO=2` — 발견 2건이 전부 엔진의 명령줄 에코. **0건이면 스캔이 눈먼 것이므로 이 검사는 0건에서 실패한다** |

| 머티리얼 (Development) | 통과 | **패키지** 실행 로그에서 실패 0건. 같은 실행에서 `LogInit` 76건 양성 대조 |

## M6이 고친 결함

패키징은 "빌드해서 압축하는 일"이 아니었다. 다음은 전부 M6에서 처음 드러났다.

- **게임 타깃이 한 번도 컴파일된 적이 없었다** — 테스트 4파일이 `#if WITH_DEV_AUTOMATION_TESTS`만으로
  가드돼 있었는데 그 매크로는 게임 Development 빌드에서도 1이라 에디터 전용 `UnrealEd` 헤더를 끌어왔다.
- **MCP 플러그인이 그대로 출하될 뻔했다** — 무조건 활성 + 모듈 `Type: Runtime`. `"TargetAllowList": ["Editor"]`로
  막았다(플러그인 자체는 `CaptureViewport` 검증 채널 때문에 유지).
- **쿡이 깨져 있었다** — `GameFeatureData` 자산 관리자 규칙 누락. `bIsEditorOnly=True`가 아니면 패키지가
  시작 시 `AssetBaseClassLoaded` ensure에 걸린다.
- **Shipping 번들 이름 가정 오류** — Shipping은 `Aquarium-Mac-Shipping.app`을 만드는데 스크립트가
  `Aquarium.app`을 가정해, 성공한 패키지를 "없음"으로 보고하고 Shipping 검증을 아예 돌리지 못했다.
- **`DefaultEngine.ini`의 죽은 MCP 절**이 쿡된 pak에 구워지고 있었다. 삭제했다.
- **OFL 1.1 사본 미동봉** — 폰트는 들어갔지만 라이선스 전문은 패키지에 없었다. `Content/Licenses/`를
  NonUFS로 스테이징해 닫았다. 검사는 수정 전 **양쪽 구성 FAIL** → 수정 후 **양쪽 `ok`**였다.

## 검사가 아무것도 검사하지 않던 네 건

이 프로젝트의 가장 비싼 교훈이고, M6 하나에서만 네 번 반복됐다.

| 계획서대로 했다면 | 실제로 무는 형태 |
|---|---|
| `tr -d '-='` — macOS `tr`이 옵션으로 파싱해 출력이 빈다. 접두 패턴도 `AquariumNoFlee`를 놓친다 | 소스에서 `TEXT("…")`까지 뽑는다 — 실제 **11개** |
| "게임 빌드 로그에서 MCP 0건" — **대조군에서도 0건**(UBT는 플러그인 이름을 stdout에 찍지 않는다) | UBT 중간 산출물: `Aquarium.rsp` 6 → 0 |
| `strings`로 바이너리 스캔 — macOS `strings`에 **`-e`가 없어** UTF-16 `TEXT()` 리터럴이 보이지 않는다. Development 대조군도 0/11이 나와 Shipping의 0은 무의미했을 것이다 | `scripts/aq_scan.py`가 ascii·utf16le 양쪽을 스캔 |
| 패키지 머티리얼 `WorldGridMaterial` 단독 grep — 멀쩡한 빌드의 `LogStreaming` 적재 안내에 걸려 첫 실행부터 빨간불 | 실패 메시지로 좁히고, 좁힘이 눈멀게 하지 않도록 `LogInit` **양성 대조**를 같은 실행에서 단언 |

## 아이에게 주는 빌드

**Shipping 구성.** Development는 SRS 성능 측정과 자동 캡처를 위해 존재하며 개발 플래그를 갖고
있다. 패키지는 저장소 밖에 있고(재현 명령은 [`docs/SETUP.md`](../SETUP.md) 12단계) 커밋하지 않는다.

## 사용자가 직접 확인해야 하는 5가지 — 2026-09-21 전부 수행, 전부 통과

헤드리스로는 **원리적으로** 확인할 수 없는 것들이다. 이것이 "빌드됨"과 "검증됨" 사이에 남아 있던 전부이고,
**다섯 항목 전부 2026-09-21에 수행되어 전부 통과했다.** 확인은 아이가 실제로 받는 구성 —
**패키지 Shipping 빌드, 창 모드 1600×900** — 에서 이루어졌다.

1. **창 포커스 (F-06, M3부터 이월)** — **통과.** 창 모드로 입장해 방향키로 움직이는 중 다른 앱으로
   갔다 돌아왔을 때 물고기가 순간이동하지 않고 제자리에서 이어졌고, 방향키는 **떼어진 상태**로
   시작했다. **M3부터 이월돼 있던 이 항목은 이것으로 닫혔다.**
2. **나가기 버튼 호버 가드 (M5)** — **통과.** 나가기 버튼 **바로 뒤로 물고기가 지나갈 때** 버튼을
   눌렀고, 초기 화면으로 돌아가되 **버튼 뒤 물고기는 놀라 달아나지 않았다.**
3. **Shipping 빌드를 손으로 플레이 (이 확인은 대체 수단이 없다)** — **통과.** Shipping은 개발
   플래그가 없어 자동 입장도 자동 캡처도 불가능해 **그 게임 플레이는 M6의 어떤 자동 수단으로도 한
   번도 확인되지 않았다.** 위 출하 검증표의 "머티리얼 (Shipping)"과 "화면 (Shipping)" 두 칸이
   미판정이던 이유가 이것이고, **두 칸은 이 확인으로 해소됐다.** 사용자가 입장·유영·클릭·나가기가
   모두 동작하고, **회색(기본 머티리얼) 물체가 하나도 없고**, 조명·안개·코스틱·산호 색이
   [`2026-09-21-m6-compare.png`](2026-09-21-m6-compare.png)의 오른쪽과 같아 보임을 확인했다.
   **이것은 사람의 시각 확인이지 자동 머티리얼 컴파일 로그 검사가 아니다** — Shipping에는
   로깅이 컴파일 아웃돼 검사할 로그가 애초에 존재하지 않는다.
4. **한글 IME 입력 (패키지에서는 처음)** — **통과.** Shipping 패키지에서 한글 별명을 손으로 직접
   타이핑해 입장했고, 조합 중 글자가 깨지지 않았으며 이름표에 입력한 그대로 나왔다.
5. **별명 비영속 최종 판정** — **통과.** 4번 세션을 끝낸 뒤 그 별명으로
   `./scripts/verify_privacy.sh manual`을 돌려 `PRIVACY_OK: … appears in no log, config or
   preference file`을 받았다. 샌드박스 컨테이너의 `Logs`/`Application Support`/`Preferences`,
   `~/Library/Logs/Aquarium`, Epic 지원 디렉터리, 프로젝트 `Saved/{Logs,Config,SaveGames,Crashes}`를
   훑어 **0건**이다. 이것이 SRS 52행에 대한 유일하게 정직한 답이다 — 자동 실행은 별명을 명령줄로
   넣으므로 판정이 될 수 없다. **입력한 별명은 실제 아이 이름이라 이 저장소 어디에도 적지 않는다**
   (문서에 쓰는 예시 별명은 계속 가공의 "니모"다).

## 남은 제약 — 숨기지 않는다

- **Shipping 빌드의 게임 플레이와 머티리얼 상태는 여전히 자동으로는 검증되지 않는다.** 개발 플래그가 없고
  로깅이 컴파일 아웃된다는 것이 바로 그 이유이고, 그것은 결함이 아니라 의도다. 위 3번의 **사용자 육안
  확인이 이 자리를 덮었고**, 앞으로 Shipping을 다시 만들 때마다 같은 육안 확인이 필요하다(자동화로
  대체할 수단은 설계상 없다).
- **UBT `exit 65`는 원인 미특정으로 남았다.** 동일 명령이 셸에서는 `env -i`로도 성공하고 UBT 액션
  실행기의 자식일 때만 실패한다. 유력한 남은 설명은 **Xcode 27.0이 UE 5.8의 문서화된 26.0 최소 /
  26.1.1 권장 범위 밖**이라는 것이다 — Xcode 26.1.1로 내리는 것은 우회가 아니라 정상화일 가능성이
  높지만 **설치는 사용자 결정이라 시도하지 않았다.** `package_mac.sh`가 우회를 내장하므로 패키징은
  막히지 않는다. 진단은 [`2026-09-21-m6-ubt.md`](2026-09-21-m6-ubt.md).
- **역투영 경로(클릭)는 Automation으로 검증되지 않는다** — `-nullrhi`에 게임 뷰포트가 없다.
  1차 방어선은 M5의 클릭 로그 CSV다.
- **포트 검사는 약한 검사다** — MCP 배제의 1차 근거는 코드 스캔이다.
- **4K 품질 모드는 범위 밖이다** — SRS가 별도 검증이라고 적었다.
- M4a~M5에서 이월된 시각 항목(비늘 이방성, TubeCoral 실루엣이 말뚝 울타리처럼 읽히는 것, 부채
  산호와 가지 산호의 구분, 동종 무리 육안 확정)은 M6이 건드리지 않았다. 각 마일스톤 계획의
  "구현 중 발견한 후속 항목" 절에 그대로 있다.
