# M2b 설계 — 배경 물고기 군집과 산호초·바위

작성일: 2026-09-20 · 상태: 사용자 승인(대화), 위임 실행

## 목표

산호초 바다를 "채워진" 장면으로 만든다: 배경 물고기 36마리가 서로 다른 깊이·크기·속도로 자율 유영하고, 바닥에 산호와 바위가 놓인다. 사용자 요청(2026-09-20)인 "내 물고기 외 30~40마리 + 산호초·바위"를 충족한다.

## 결정 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| 종 구성 | 기존 2종(블루탱·클라운피시) + 새 3종(노란탱·나비고기·담셀피시) | 다양성과 제작 시간의 균형 |
| 종 정의 방식 | `fishlib.build_species(spec)` 데이터화(M2 리뷰가 지목한 선행 리팩터) 후 새 종 추가 | 다섯 번째 종까지 복붙하면 규약이 갈라진다 |
| 바위 | Poly Haven CC0 3D 모델 | 실사 스캔, 라이선스 단순 |
| 산호 | Blender 절차 생성 3종(가지·판·뇌 산호) | 무료 고품질 산호 모델이 드물고, 절차 생성은 재현 가능 |
| 움직임 | 개별 자율 유영 + 깊이·크기·속도 분산 | 기존 규칙 계층 그대로 사용, 프레임 예산 안전. 무리(보이즈) 행동은 M4로 이월 |
| 배치 방식 | 고정 시드로 스크립트가 액터를 배치하고 `.umap`에 저장 | 에디터·스틸에 그대로 보이고 재현·검증 가능 |

검토한 대안: 기존 2종만 색·크기 변이(다양성 부족), 새 종 5개 이상(M4 실사 반복 때 전부 다시 다듬어야 함), 런타임 스포너(에디터 스틸에 안 보임), 보이즈 군집(규칙 계층 신규 기능이라 M2b가 길어짐).

## 구성 요소

### 1. `fishlib` 데이터화 (선행 리팩터)
- `build_species(spec)`: `spec = {name, body:(len,h,w,taper_z,taper_y), fin_thickness, fins:[(name, verts_fn(L, half_height_fn), faces)], color_fn, rig:{pec_z, tail_tip_x, pec_span_y, pec_drop_z}, cam_loc, export_dir}` → 메시·리깅·베이크·FBX·프리뷰까지 수행하고 `(verts, bones, unweighted, root_max_w, pec_stray)`를 돌려준다.
- 공통 헬퍼: `axis_band_mask(nt, axis_socket, center, width, edge)`(줄무늬·띠), `mix_over(nt, base, mask, color)`, `pec_stray_count(body, half_len)`.
- `make_bluetang.py`, `make_clownfish.py`는 spec만 남는다. **산출물 불변**(FBX 본·치수·정점 수, 베이크 PNG 바이트)을 증명한다.
- 프리뷰 파일명 `preview_<species>.png`로 통일한다.

### 2. 새 물고기 3종
| 종 | 몸길이 | 형태·색 |
|---|---|---|
| 노란탱 (YellowTang) | 20 cm | 블루탱과 같은 납작한 타원, 전체 노랑(0.95, 0.75, 0.05), 흰 꼬리자루 |
| 나비고기 (Butterflyfish) | 14 cm | 높은 몸통(h/len ≈ 0.75), 노랑 바탕에 검은 눈띠 1개와 사선 줄무늬 |
| 담셀피시 (Damselfish) | 7 cm | 작고 둥근 몸통, 진한 파랑(0.05, 0.15, 0.6), 꼬리 쪽 밝은 청색 |

모두 같은 본 규약(Root 비변형, Spine0..5, Tail, PecL, PecR)을 지킨다.

### 3. 산호·바위
- `assets/blender/make_corals.py`: 절차 생성 3종을 하나의 스크립트로 만든다.
  - 가지 산호(BranchCoral): 재귀 분기 실린더, 깊이 3, 끝으로 갈수록 가늘어짐. 높이 60~80 cm.
  - 판 산호(PlateCoral): 넓은 원반에 노이즈 변위, 가장자리 물결. 지름 80~120 cm.
  - 뇌 산호(BrainCoral): 구를 눌러 만든 반구에 노이즈 홈. 지름 50~70 cm.
  - 각각 절차 텍스처를 1024²로 베이크(산호는 물고기보다 작게 잡아 메모리 절약), FBX로 정적 메시 내보내기, 프리뷰 렌더.
- 바위: Poly Haven API(`t=models&c=rock`)에서 CC0 모델 2~3개를 받아 `assets/models/rocks/`에 두고 `docs/ASSETS.md`에 기록한다.
- `Scripts/import_props.py`: 산호 FBX와 바위 모델을 `/Game/Props/`에 스태틱 메시로 임포트하고 머티리얼을 연결한다(종 임포트와 같은 idempotent 규약, `PROPS_OK` 마커).

### 4. 장면 배치 (`build_reef_m1.py`)
고정 시드 `SCHOOL_SEED`, `PROP_SEED`로 `random.Random`을 써서 전부 결정적으로 뽑는다.

- 물고기 36마리(`SCHOOL_COUNT`): 종 가중치(담셀 40%, 나머지 15%씩), 평면 원점 X∈[330, 700]·Y∈[−250, 250]·Z∈[110, 200], 반폭 120~220, 반높이 40~60, 액터 스케일 0.75~1.3, `MaxSpeed` 25~55 cm/s, 개별 시드. 플레이어 평면(X=220)은 비운다.
- 소품 14개(`PROP_COUNT`): 산호·바위를 바닥(z≈0)에 X∈[150, 800], Y∈[−400, 400]에 놓고 무작위 yaw와 0.7~1.4 스케일. 카메라 정면 중앙(|Y| < 60 이면서 X < 320)은 비워 시야를 확보한다.
- 물고기 평면 최저 z는 110 − 60 = 50 cm, 산호 최대 높이 80 cm이므로 X 밴드가 겹치면 물고기가 산호를 통과할 수 있다. 충돌 처리는 넣지 않는다(M4 이후 검토 항목으로 기록).

### 5. 카탈로그
`AAquariumGameMode`의 기본 카탈로그를 5종으로 늘린다. 배정 도달성 테스트를 5종 기준으로 갱신한다.

### 6. 성능 측정 시작
개발 전용 `-AquariumFrameStats=<파일>`: 컨트롤러가 매 프레임 `DeltaSeconds`를 누적하고 종료 시 CSV로 쓴다. `scripts/measure_m2b_perf.sh`가 1920×1080 `-game`으로 30초 예열 + 60초 측정 후 평균 fps와 95백분위 프레임 시간을 계산해 `docs/reviews/<날짜>-m2b-perf.md`에 기록한다. SRS 목표(60 fps, 95p ≤ 22 ms) 달성 판정은 M6에서 하고, 여기서는 현재 수치를 남긴다.

## 검증

| 계층 | 검증 |
|---|---|
| 리팩터 | 블루탱·클라운피시 FBX 본·치수·정점 수 불변, 베이크 PNG 바이트 동일 |
| 새 에셋 | 새 종 3개 FBX 본 계약 일치, 산호 3종 정점 수·치수 출력, 프리뷰 육안 확인 |
| 장면 | `verify_scene.py`: FishActor 수 = `SCHOOL_COUNT`, 5종 모두 등장, 모든 배경 평면 X ≥ 330, 스케일 0.75~1.3, 소품 수 = `PROP_COUNT`, 플레이어 평면(X < 300)에 배경 물고기 없음 |
| Unreal | 기존 24개 유지 + 카탈로그 5종 배정 도달성 |
| 시각 | 20초 관람 영상과 스틸 2장(전경 산호 포함 / 군집) |
| 성능 | 위 CSV와 요약 문서 |

## 데이터·오류 처리

- 산호·바위 임포트 실패 시 해당 소품만 건너뛰고 경고를 남긴다(장면 생성은 계속).
- 종 메시 로드 실패는 이미 카탈로그에서 제외된다(M2 구현).
- 물고기 수를 늘려 프레임이 크게 떨어지면 `SCHOOL_COUNT`를 낮추지 말고 수치를 기록한 뒤 M4/M6 조정 항목으로 남긴다.

## 범위 밖

무리(보이즈) 행동, 물고기·산호 실사 정밀화, 물고기와 소품의 충돌(모두 M4), 방향키 조종(M3), 클릭 도망(M5), 패키징·성능 판정(M6).
