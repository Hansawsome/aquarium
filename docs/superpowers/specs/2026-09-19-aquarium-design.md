# Aquarium 설계

작성일: 2026-09-19 · 분류: 신규 프로젝트 / Architectural

## 합의한 의도

초등학생이 맥북에서 별명으로 입장해 실사에 가까운 산호초 바다를 감상하고 자신의 물고기 한 마리를 방향키로 조종한다. 다른 물고기는 자동 유영한다. 카메라는 잠수부 위치에 머문다. 태블릿의 물고기 터치에는 도망 반응을 제공한다. 무료 에셋만 사용한다.

상세 범위는 [PRD](../../PRD.md), 동작과 인수 기준은 [SRS](../../SRS.md)를 함께 검토한다.

## 접근 선택

| 선택지 | 장점 | 제약 | 결정 |
|---|---|---|---|
| Unreal Engine 5 + Blueprint/C++ | 수중 조명·재질·애니메이션을 함께 다루는 네이티브 제작 환경 | 도구 설치가 크고 Mac 기능별 지원·태블릿 최적화 검증 필요 | 사용자 논의에 따른 우선안 |
| TypeScript + Three.js | 브라우저 접근과 배포가 편리 | 실사 장면의 품질·기기별 최적화를 직접 구성해야 함 | 초기 선택에서 제외 |

엔진의 정확한 버전은 설치 가능한 안정 버전과 호환 Xcode를 함께 확인한 후 고정한다. Unreal 5의 기능을 모두 사용할 수 있다고 가정하지 않으며 실험적 렌더링 기능은 초기 필수 요소로 삼지 않는다.

## 컴포넌트

- **Session**: 별명 검증, 입장 상태, 물고기 선택과 소유 관계. 별명은 인증 정보가 아니다.
- **FishSimulation**: 방향 입력, 가속·감속, 유영/도망/회복 상태, 경계 처리. C++ 규칙으로 분리한다.
- **FishActor**: 규칙 상태를 월드 좌표와 애니메이션 파라미터에 연결한다.
- **Interaction**: 방향키·마우스·후속 터치 입력을 처리하고, 레이캐스트 결과를 대상 물고기와 수영 평면 좌표로 변환한다.
- **ReefScene**: 고정 카메라, 조명, 수중 효과, 산호 배치, 유영 영역을 소유한다.
- **UI**: 별명 입력과 오류 표시, 내 물고기 이름표, 나가기. 학생에게 엔진·디버그 설정은 노출하지 않는다.

## 입력에서 화면까지

별명 제출 → Session 검증 → 주입 가능한 난수로 FishDefinition 선택 → FishActor 생성과 소유 지정 → 이름표 표시.

방향키 → 화면 기준 입력 벡터 → FishSimulation의 상태별 목표 속도 → 가속/경계 처리 → FishActor 위치·회전 → 유영 애니메이션.

클릭/터치 → 가장 앞의 물고기 적중 → 터치 위치를 수영 평면으로 투영 → 도망 방향 계산 → 도망/회복 타이머 → 원래 자동/사용자 제어로 복귀.

## 표현과 에셋 제작

Blender에서 모델 비율·리깅·유영 애니메이션을 준비하고 Unreal에서 재질·빛·후처리를 조합한다. Blender 자동화는 Python API를 우선 검토하며 MCP는 실제 도구가 필요하고 확인됐을 때 연결한다.

첫 시각 검토용 장면은 한 마리 물고기와 소규모 산호 군락이다. 제작한 소스와 게임용 파생 에셋을 구분한다. 공개 저장소에 포함할 수 있는 라이선스의 무료 원본을 사용하고, 나머지는 구매 없이 직접 제작한다.

## 검증 설계

TDD로 게임 규칙과 연동 동작을 구현한다. 테스트 실행 → 예상한 동작 실패 확인 → 최소 구현 → 통과 확인 → 정리 순서를 기록한다. 테스트가 실행 환경/컴파일 오류로 실패하면 해당 오류를 고치고 의도한 실패를 다시 확인한다.

시각적 실사성은 단위 테스트로 증명할 수 없다. 산호초 장면과 물고기 움직임을 실제 렌더링하여 사용자 검토와 성능 측정을 별도로 수행한다. 규칙 테스트 통과, Unreal 빌드 통과, 화면 검토 완료를 각각 보고한다.

## 현재 환경과 진행 순서

현재 로컬 폴더는 원격 aquarium 저장소와 연결했다. 기존 저장소에는 초기 커밋과 `.gitkeep`만 있었다. 기본 설치 경로에 Unreal·Blender·정식 Xcode가 없어 그래픽 빌드 검증은 아직 할 수 없다.

설계 문서 검토 → TDD 구현 계획 작성 및 실행 방식 선택 → 호환 도구 준비 → 규칙 테스트와 최소 장면 → macOS 체험 기능 → 시각/성능 조정 → 태블릿 확장 순서로 진행한다.

## 검토 상태

- 대화에서 제품 방향·입력 방식·무료 에셋·TDD를 합의했다.
- 이 문서와 연결된 PRD/SRS의 자체 일관성 검토와 로컬 링크 검사를 마쳤다.
- 문서 자체의 사용자 검토는 아직 받지 않았다.
- 구현 계획, 게임 코드, 제품 의존성 설치는 아직 시작하지 않는다.
