# SRS — Aquarium

작성일: 2026-09-19 · 상태: 설계 초안

수치와 세부 정책은 개발 시작을 위한 제안값이다. 실제 시제품에서 조정하면 이 문서와 해당 테스트를 함께 수정한다.

## 기능과 인수 기준

| ID | 명세 | 검증 |
|---|---|---|
| F-01 | 별명 앞뒤 공백을 제거한다. 빈 값·공백만 있는 값·줄바꿈/제어 문자를 거부한다. 최대 12개 사용자 인식 문자로 제한한다. 한글 조합 입력과 이모지의 처리도 검증한다. | 입력 규칙 테스트 + 실제 한글 입력 |
| F-02 | 유효한 별명 입력 시 세션을 하나 만들고 한 마리만 소유 대상으로 지정한다. 연속 클릭으로 중복 생성하지 않는다. | 세션 단위/연동 테스트 |
| F-03 | 유효한 물고기 목록에서 난수로 한 항목을 배정한다. 테스트에서는 난수 공급자를 주입한다. 빈 목록이면 입장을 막고 오류를 표시한다. | 첫/마지막 항목, 빈 목록 테스트 |
| F-04 | 내 물고기 위에 별명을 표시한다. 일반 물고기에는 이름을 표시하지 않는다. 한글 폰트는 패키지에 포함하고 출처를 기록한다. | UI 연동 테스트 + 패키지 시각 확인 |
| F-05 | ↑/↓는 화면의 위/아래, ←/→는 좌/우 이동이다. 대각선 속도는 정규화하고 반대 키는 상쇄한다. | 입력 벡터 테스트 |
| F-06 | 키를 놓으면 부드럽게 감속한다. 창 포커스를 잃으면 입력을 해제하고 시뮬레이션을 일시정지한다. 복귀 시 큰 시간 간격으로 순간이동하지 않는다. | 속도 변화·포커스 연동 테스트 |
| F-07 | 고정 카메라의 이동 가능 영역 안에서 물고기 전체가 보이도록 여백을 둔다. 경계에서는 회피하며 안전 제한으로 이탈을 막는다. | 각 경계·모서리·도망 중 경계 테스트 |
| F-08 | 주변 물고기는 화면 안에서 자율 유영한다. 모든 물고기가 같은 경로와 박자로 움직이지 않도록 개체별 위상과 목표를 둔다. | 시드 고정 유영 테스트 + 영상 확인 |
| F-09 | 클릭으로 가장 앞의 적중 물고기 한 마리만 도망 상태로 만든다. 빈 바다 클릭은 아무 물고기에도 영향을 주지 않는다. | Unreal 충돌/레이캐스트 연동 테스트 |
| F-10 | 클릭 지점에서 멀어지는 화면 방향으로 회전·가속한다. 중심을 정확히 클릭해 방향이 0이면 현재 진행 방향, 정지 상태면 화면 중심 쪽의 유효 방향을 쓴다. | 방향·중심 적중·정지 테스트 |
| F-11 | 도망 0.8초 → 회복 1.2초 → 원래 제어 상태로 돌아온다. 도망 중 재입력은 무시하고 회복 중 재입력은 도망을 재시작한다. | 시간 경계·반복 클릭 상태 전이 테스트 |
| F-12 | 내 물고기도 도망 중에는 방향키보다 도망 동작을 우선한다. 회복 단계부터 현재 방향키 입력을 다시 적용한다. 배경 물고기는 자동 유영으로 복귀한다. | 소유 여부별 복귀 테스트 |
| F-13 | 회전·꼬리 진폭·유영 주기는 속도와 상태를 따른다. 물고기가 순간적으로 좌우 반전하거나 미끄러지지 않는다. | 애니메이션 연동 테스트 + 영상 검토 |
| F-14 | 나가기를 선택하면 물고기 소유와 별명을 지우고 초기 화면으로 돌아간다. 다시 입장해도 이전 세션이 남지 않는다. | 재입장 회귀 테스트 |

## 시각 기준

- 고정된 잠수부 시점. 카메라 추적 없음. 약한 흔들림은 끌 수 있게 하고 화면을 과하게 왜곡하지 않는다.
- 전경 산호·바위, 중경 물고기, 원경의 푸른 수중 흐림으로 깊이를 만든다.
- 수면에서 내려오는 빛과 바닥의 움직이는 빛무늬, 절제된 부유 입자를 표현한다.
- 사실적인 비율과 표면 재질, 연속적인 몸통·지느러미 동작을 사용한다. 임시 도형은 최종 그래픽으로 승인하지 않는다.
- 30초 이상의 동일 경로 영상으로 정지 화면뿐 아니라 회전·가속·도망을 확인한다.

## 성능 목표 — 실측 전 보장 아님

- 기준 기기: M5 10코어 GPU / 통합 메모리 24GB 맥북프로.
- 첫 측정 장면: 제어 물고기 1마리 + 배경 물고기 19마리, 1920×1080 내부 렌더링.
- 패키징한 개발 빌드에서 30초 예열 후 3분 동안 측정한다. 평균 60fps, 95백분위 프레임 시간 22ms 이하를 초기 목표로 둔다.
- 출력 해상도·내부 렌더링 해상도·업스케일링·그래픽 설정을 결과와 함께 기록한다. 4K 출력은 별도 품질 모드로 검증한다.
- 목표 미달이면 빛/그림자, 투명 효과, 산호 밀도와 LOD를 조정한다. 근거 없이 목표를 달성했다고 보고하지 않는다.

## 구조와 테스트 경계

1. C++ 규칙 계층: 입력 방향, 속도, 경계, 물고기 상태와 난수 선택. 렌더링에 의존하지 않고 결정적으로 테스트한다.
2. Unreal 연동 계층: 입력 이벤트, 세션, Actor 생성, 클릭 적중 판정, 카메라 좌표 변환, UI. Unreal Automation Tests로 검증한다.
3. 표현 계층: Blueprint, Animation Blueprint, 재질, 조명, 산호 장면. 실제 실행 영상과 성능 측정으로 검증한다.

규칙 테스트에서는 고정 시드/명시적 시간 간격을 사용한다. 프레임 시간이 0일 때와 비정상적으로 클 때도 검증한다. 테스트를 위한 별도 규칙 복제품을 만들지 않고 실제 앱이 같은 규칙 코드를 사용한다.

## 데이터와 장애 처리

- 별명은 메모리에만 유지하며 저장·전송·로그 기록하지 않는다.
- 에셋 실패 시 유효한 대체 물고기가 있으면 사용하고, 없다면 입장 화면에 복구 가능한 오류를 표시한다.
- 한국어 폰트 누락, 입력 중복, 창 포커스 전환, 화면 비율 변경을 회귀 항목에 포함한다.
- 앱 실행에 MCP나 외부 AI 서비스 연결이 필요하지 않도록 한다.
